# Tweet Service — Smithy API

A CRUD REST API for a tweet flow, modelled in [Smithy 2.0](https://smithy.io/2.0/) and compiled to a TypeScript client, TypeScript server, and OpenAPI spec.

## Prerequisites

- [Smithy CLI](https://smithy.io/2.0/guides/smithy-cli/cli_installation.html) ≥ 1.70.0
- Node.js ≥ 16 and npm

## 1. Build the Smithy model

From the project root, run:

```bash
smithy build
```

This validates the models and runs all codegen plugins, producing three artifacts:

```
build/smithy/typescript-client/typescript-client-codegen/   ← TypeScript client
build/smithy/typescript-server/typescript-server-codegen/   ← TypeScript server
build/smithy/openapi/openapi/TweetService.openapi.json      ← OpenAPI spec
```

## 2. Compile the TypeScript client

```bash
cd build/smithy/typescript-client/typescript-client-codegen
npm install
npm run build
```

Three output formats are generated:

| Directory | Format | Use |
|---|---|---|
| `dist-cjs/` | CommonJS | Node.js `require()` |
| `dist-es/` | ES Modules | Bundlers (webpack, esbuild) |
| `dist-types/` | Type declarations | IDE intellisense / `.d.ts` |

## 3. Package the client for consumption

```bash
npm pack
# → example-tweet-client-1.0.0.tgz
```

This creates a tarball — a snapshot of the distributable files that mirrors exactly what would be published to npm. Use it to install the client in another project:

```bash
npm install ../path/to/example-tweet-client-1.0.0.tgz
```

### Local path (dev only)

For a faster dev loop you can reference the folder directly instead of packing:

```json
"dependencies": {
  "@example/tweet-client": "file:../x-test/build/smithy/typescript-client/typescript-client-codegen"
}
```

> Note: a `file:` path symlinks the folder, so live edits are picked up immediately but it does not simulate a real npm publish.

## 4. Client usage example

```ts
import { TweetServiceClient, CreateTweetCommand } from "@example/tweet-client";

const client = new TweetServiceClient({ endpoint: "http://localhost:3000" });

const result = await client.send(new CreateTweetCommand({
  body: { authorId: "sergio", content: "Hello Smithy!" },
}));
```

## 5. Compile the TypeScript server

```bash
cd build/smithy/typescript-server/typescript-server-codegen
npm install
npm run build
```

The server package generates handler interfaces and routing logic. You implement each operation and wire it to an HTTP framework:

```ts
import { TweetServiceImpl, getHandler } from "@example/tweet-server";
import express from "express";

const impl: TweetServiceImpl = {
  async CreateTweet(input) {
    const tweetId = crypto.randomUUID();
    return { body: { tweetId, ...input.body, createdAt: new Date(), likeCount: 0 } };
  },
  async GetTweet(input) { /* fetch from DB */ throw new Error("not implemented"); },
  async UpdateTweet(input) { throw new Error("not implemented"); },
  async DeleteTweet(_input) { return {}; },
  async ListTweets(_input) { return { items: [], nextToken: undefined }; },
};

const app = express();
app.use(express.json());
app.use(getHandler(impl));
app.listen(3000, () => console.log("Listening on http://localhost:3000"));
```

## 6. Run a mock server (no code required)

The OpenAPI spec generated by `smithy build` can be served instantly using [Prism](https://stoplight.io/open-source/prism):

```bash
npx @stoplight/prism-cli mock build/smithy/openapi/openapi/TweetService.openapi.json
```

All endpoints are available immediately at `http://127.0.0.1:4010` with auto-generated example responses:

```bash
curl -X POST http://127.0.0.1:4010/tweets \
  -H "Content-Type: application/json" \
  -d '{"authorId":"sergio","content":"Hello Smithy!"}'
```

### Server options comparison

| Approach | Effort | Real logic |
|---|---|---|
| Prism mock (step 6) | Zero code | No — auto-generated responses |
| Node `http` + generated server | ~20 lines | Yes |
| Express + generated server (step 5) | ~30 lines | Yes |

| Operation | Method | URI |
|---|---|---|

| `GetTweet` | GET | `/tweets/{tweetId}` |
| `UpdateTweet` | PUT | `/tweets/{tweetId}` |
| `DeleteTweet` | DELETE | `/tweets/{tweetId}` |
| `ListTweets` | GET | `/tweets` |
